## Mission
The product's core claim is that it separates success from failure and abstains rather than guessing. Review found three engine defects:
1. **False-PASS (S1).** On the kinematic mock with Tier A synthetic tracks from sim state (`loop.gate.grade_sim_run` / `scripts/validate_engine.build_synthetic_tracks_from_obs`; read `tests/loop/*` for how), seed 0: **B04 (short dwell) and B09 (never opens) get verdict PASS while `oracle_success` is False.** Causes found: step 3 `not moves_with(gripper, cubeA) and dwell(cubeA, cubeB, for_s=0.5)` is satisfied during the post-place wait when gripper and cube are co-stationary (`moves_with.py:~87-104` treats co-stationary as F), and `dwell` ignores its 2nd argument (`dwell.py:~45` uses only `args[0]`) so it never checks that cubeA stays *on cubeB*; a later drag/topple isn't checked. Verify by reproducing before fixing.
2. **FAIL where the spec says CAN'T TELL (S1).** `engine/steps.py` "Case C" returns FAIL when the last frame is F even though a U run ≥ `n_on` exists in the window; ARCHITECTURE §7.5 says that is CAN'T TELL. On Tier C golden fixtures (no cam_K) `moves_with.slip` σ equals its limit so gate G3 forces U on every carry frame: **every** fixture clip (including `correct_run.mp4`) is "FAIL at grasp". The honest outcome at Tier C is CAN'T TELL (reason `below_noise_floor`), never a confident FAIL, and never PASS.
3. **Perception badge lies (S2).** `pipeline/run.py:~138` always badges `[REPLAY: CACHED SAM 3.1 TRACKS]` for any supplied tracks (false for tracks projected from sim state); `render/card.py:~242` hard-codes a `[sam-3.1]` badge. Add an optional `perception_label: str | None = None` argument to `run(...)` (default keeps today's text for stored SAM tracks); card shows `[sam-3.1]` only when `RunResult.backends["perception"]` is a SAM backend, otherwise the label given (e.g. `SYNTHETIC TRACKS FROM SIM STATE · NOT PERCEPTION`).
4. **Bisect support (S2, from T02).** Add `run(..., dense_frames: set[int] | None = None)`: when given, the G2 scene scan and per-frame evaluation use only those frames, other frames are U, and temporal atoms need history inside the set (see CHANNEL IMPL-2 entry and `pipeline/bisect.py::_evaluate_dense` for the semantics it mirrors). Default `None` must leave today's behaviour bit-identical (existing tests prove it). Do NOT edit bisect.py; tell ORCH in your report that bisect can swap its mirror for the call.
5. **Reference series for blame (S2, from T01).** Make `pipeline/run.py` (or a small helper in the pipeline) able to emit the effector→place-target xy distance series into the trace so `blame.facts.reference_pred_frames` / `dt_before_reference_s` can be filled (see CHANNEL IMPL-1 DONE entry, item 3).
